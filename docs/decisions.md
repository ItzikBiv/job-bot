# Decision log

Settled decisions. Supersede an entry by adding a new one that names the old ID; don't edit history.

| ID | Date | Decision | Why |
|----|------|----------|-----|
| D1 | 2026-10-09 | **Human approves every submission.** The bot finds jobs, tailors the CV, and pre-fills the application, but nothing is sent until the user approves it. | Avoids account bans on sites that forbid automated applying (e.g. LinkedIn), and catches mistakes before an employer sees them. |
| D2 | 2026-10-09 | **Automate sources with public job APIs first** (company career pages on Greenhouse, Lever, Comeet and similar). Aggregators that forbid scraping or bots (LinkedIn, etc.) are out of scope for automation; at most, the user applies to them manually from a list the bot prepares. | ToS compliance and reliability. |
| D3 | 2026-10-09 | **Truthful tailoring only.** CV tailoring may reword, reorder, emphasise, and trim content from the user's master CV; it must never invent experience, skills, titles, dates, or credentials. | Honesty, and fabricated claims get caught in interviews and background checks. |
| D4 | 2026-10-09 | **Process size: Medium.** Brief → PRD → security decision framing → architecture → riskiest-path spike → epics/stories → readiness → sprints. | Multiple integrations, credentials and personal data, and external actions. |
| D5 | 2026-10-14 | **Supersedes D2's "apply via ATS APIs".** No ATS offers a public apply API to job seekers (Greenhouse, Lever and Ashby submit endpoints need the employer's key). The bot produces an **application packet** per job: tailored CV (HTML + PDF), filled-in answers, cover note, and the apply link. The user reads it and submits it himself. Browser pre-fill of Greenhouse/Lever forms is a later feature. Reading postings via public ATS APIs (D2) still stands. | Research digest in the brief addendum; the user said "I will just read it and apply". |
| D6 | 2026-10-14 | **Personal data never enters git.** The repo is public. Master profile, CVs and packets live in the git-ignored `private/` folder and reach the user through private channels (a private claude.ai artifact, session files). Tests use a fictional fixture profile. | Phone, address and employment history would be exposed in a public repo. |
| D7 | 2026-10-14 | **Supersedes D4's ordering.** The user asked to see real applications now, so the first slice ships before the PRD: a packet pipeline (profile → tailoring → CV render → review page). For now Claude does the tailoring in-session. Unattended LLM tailoring (which needs an API key and handles untrusted job text) waits for `bmad-security-decision-framing`. The PRD and architecture follow, informed by this slice. | The user delegated the call ("do whatever you think is right"); the operating model rule is to write less code, not less product. |
| D8 | 2026-10-14 | **How D3 is enforced.** Code (`jobbot/truth.py`) blocks unknown ids, moved bullets, reordered timelines, and reworded text that adds numbers, number words, technologies or credentials missing from its cited sources. It cannot judge meaning, so every reworded line is also listed for the user on the review page. Profile items marked `confirm` (claims found in only one of the user's CVs) are left off tailored CVs until he confirms them. | Independent code review showed a regex gate can't fully prove truthfulness, and recruiter review flagged unconfirmed claims as the main credibility risk. |
| D9 | 2026-10-25 | **Every CV goes through the CV-upgrade agent before the user sees it.** For each tailored CV, the `cv-upgrader` subagent (`.claude/agents/cv-upgrader.md`) reviews it against the job description with the cv-reviewer skill, improves the tailoring within D3, passes the truthfulness gate, and visually checks the one-page PDF. The main agent then re-verifies (gate, page count, a look at the render) before sending. | The user asked that every CV be upgraded and perfect before it is sent; a right-to-left punctuation bug showed that visual checks are needed too. |
| D10 | 2026-10-26 | **Three-agent pipeline for every new job** (supersedes the single-agent step in D9; jobs prepared before this date are not re-run). 1) `cv-upgrader` makes the content as strong as it truthfully can be. 2) `cv-designer` improves only the design block (stat tiles, bold phrases, palette, density, layout), keeping the user's original design language. 3) `cv-scorer` scores 0–100 with a fixed rubric and routes feedback to the upgrader or designer. Loop until PASS (≥85, no truth issue) or 2 revision rounds, then the main agent verifies (gate, one page, a look at the render) and sends. | The user saw CVs drifting from their original look and asked for a design agent and a scoring agent that feeds back to the others, applied only to jobs from now on. |
